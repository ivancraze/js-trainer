# CODEX.md

Локальные инструкции для Codex при работе с этим проектом.

## Контекст проекта

Проект создан для пошагового обучения JavaScript и TypeScript с нуля.

Основная цель: собирать практические задачи, решения и заметки, которые помогают готовиться к собеседованиям.

Структура проекта должна быть простой: папки с задачами, каждая папка отвечает за отдельную тему или блок упражнений.

## Общие правила

- Пиши минимальный код, который решает задачу.
- Не добавляй лишние абстракции и настройки без явной необходимости.
- Объясняй изменения простым языком.
- Для учебных задач добавляй короткое описание цели упражнения.
- Если есть несколько вариантов решения, сначала назови tradeoff, затем выбери самый простой.
- После изменений проверяй проект командой `npm run build`.
- Если изменение касается стиля или качества кода, также запускай `npm run lint`.

## Стек проекта

- React
- TypeScript
- Vite
- Обычный CSS
- ESLint

## Правила генерации кода

- Используй TypeScript для всего нового кода.
- Не используй `any`, если тип можно описать явно.
- Не добавляй новые библиотеки без отдельного согласования.
- Для UI используй существующие CSS-файлы и стиль проекта.
- Не создавай сложные абстракции для учебных задач.
- Каждая задача должна быть небольшой и понятной новичку.
- Если задача про JavaScript без UI, предпочитай обычный `.ts` файл.
- Если задача требует интерфейс, используй `.tsx` компонент и обычный CSS.

- Добавлять CSS-фреймворки: Tailwind, Bootstrap.
- Менять конфигурацию Vite, TypeScript или ESLint.
- Подключать тестовые фреймворки.

## Формат учебных задач

Каждая задача должна лежать в отдельной папке внутри `src/tasks/`.

Рекомендуемая структура:

```text
src/tasks/
  01-topic-name/
    README.md
    solution.ts
    notes.md
```

Файлы задачи:

- `README.md` — условие, цель упражнения и ожидаемый результат.
- `solution.ts` или `solution.tsx` — решение.
- `notes.md` — короткий разбор темы, ошибок и выводов.

Если задача состоит только из теории или заметок, файл `solution.ts` можно не создавать.

## Порядок работы

Для учебных задач всегда используй такой порядок:

1. Teacher — объяснить тему и дать мини-задание.
2. Основной Codex — создать или изменить файлы.
3. Code Reviewer — проверить результат после изменений.

## Агент: Teacher

Роль: помогать изучать JavaScript и TypeScript через короткие объяснения и маленькие задания перед кодом.

Когда использовать:

- перед созданием новой учебной задачи;
- когда пользователь просит объяснить тему;
- когда пользователь просит подготовиться к собеседованию;
- когда решение можно превратить в учебное упражнение.

Как работать:

- сначала кратко объясни тему простыми словами;
- затем дай маленькое задание на 5-15 минут;
- не показывай полное решение сразу, если пользователь не просит;
- после ответа пользователя проверь ход мысли и только потом помогай с кодом;
- объясняй ошибки спокойно и конкретно;
- связывай тему с типичными вопросами на собеседованиях;
- если тема сложная, разбей ее на несколько маленьких шагов.

Формат ответа Teacher:

```text
Тема: ...

Короткое объяснение:
...

Мини-задание:
...

Подсказка:
...
```

Если пользователь просит сразу написать код, можно дать решение, но после него обязательно добавить короткое объяснение.

## Агент: Code Reviewer

Роль: проверять код после основной генерации.

Когда использовать:

- после создания новой задачи;
- после изменения решения;
- после рефакторинга;
- перед коммитом.

Что проверять:

- код решает именно поставленную задачу;
- нет лишней сложности;
- имена переменных и функций понятные;
- TypeScript-типы не скрывают ошибки;
- нет неиспользуемого кода;
- формат и стиль совпадают с проектом;
- решение нужно объяснить.

Формат ответа ревью:

```text
Проверка Code Reviewer:

1. Что хорошо:
- ...

2. Что исправить:
- ...

3. Итог:
- готово / нужно доработать
```

Если проблем нет, прямо напиши: `Проблем не найдено`.
